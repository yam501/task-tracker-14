# Трекер задач

Домашнее задание по базам данных. Тема 14.

Приложение хранит сотрудников, проекты, задачи и сведения о репозиториях. Сотрудник участвует в нескольких проектах, а проект может иметь несколько участников. В участии записаны роль сотрудника и дата включения в проект.

Используются Java 17, Spring Boot 3.5.16, Spring Data JPA, Hibernate и PostgreSQL 16. Демонстрация выполнена через консольный `DemoRunner`.

## Запуск из IntelliJ IDEA

Нужен запущенный Docker Desktop с Linux-контейнерами. Открыть `pom.xml` как Maven-проект и выбрать JDK 17 или новее. Из папки проекта запустить PostgreSQL:

```powershell
docker compose up -d db
```

Запустить `TaskTrackerApplication`. Приложение создаст таблицы, заполнит их примерами, выведет результаты запросов и завершится. Адрес БД для локального запуска: `localhost:55432`, база `task_tracker`, пользователь `student`, пароль `student`. Это локальные учебные настройки. Если порт занят, изменить его в `compose.yaml` и адрес в `application.yml`.

При установленном Maven приложение также можно запустить командой:

```powershell
mvn spring-boot:run
```

## Запуск приложения через Docker

Нужен запущенный Docker Desktop с Linux-контейнерами. Команды выполняются из папки проекта.

```powershell
docker compose up -d db
docker compose run --build --rm app
```

При первом запуске Docker скачает образы и Maven-зависимости. Hibernate создаст таблицы, сервис сохранит примеры данных, затем приложение выведет результаты запросов и завершится. Контейнер приложения удаляется после завершения, данные PostgreSQL остаются в томе.

Для повторной демонстрации:

```powershell
docker compose run --rm app
```

Данные повторно не добавляются, если в БД уже есть проекты. Ожидаемые результаты ниже относятся к исходным демонстрационным данным.

Остановка БД с сохранением данных:

```powershell
docker compose stop
```

## Схема данных

| Таблица | Основные поля | Связи |
| --- | --- | --- |
| `employees` | `id`, `name` | Сотрудник в записях участия |
| `projects` | `id`, `name`, `repository_id` | Один репозиторий, несколько задач |
| `repositories` | `id`, `url` | Репозиторий одного проекта |
| `tasks` | `id`, `title`, `status`, `project_id` | Задача относится к проекту |
| `participations` | `id`, `employee_id`, `project_id`, `role`, `joined_at` | Связка сотрудника и проекта |

В `Task.project` находится владеющая сторона связи 1:N с `@ManyToOne` и `@JoinColumn`. Обратная сторона `Project.tasks` использует `@OneToMany(mappedBy = "project")`. Метод `Project.addTask` заполняет обе стороны.

Связь N:M реализована через `Participation` с двумя `@ManyToOne`. Пара сотрудник-проект уникальна. Связь 1:1 задана в `Project.repository` через `@OneToOne`, внешний ключ `repository_id` уникален. URL репозиториев являются учебными данными, обращения к ним нет.

## Проверка задания

| Пункт | Где реализован | Как проверить |
| --- | --- | --- |
| Пять сущностей | Пакет `entity` | В БД пять таблиц |
| Двусторонняя 1:N | `Project.tasks`, `Task.project` | Раздел 1: у сайта 3 задачи, у бота 2 |
| N:M с атрибутами связки | `Participation` | Раздел 2: три участия с ролями и датами |
| 1:1 | `Project.repository` | Раздел 1: отдельный URL у каждого проекта |
| `JpaRepository` для каждой сущности | Пакет `repository` | Пять интерфейсов репозиториев |
| Запрос из имени метода | `TaskRepository.findByStatusOrderById` | Раздел 3: две задачи TODO |
| Native SQL | `TaskRepository.findByProjectIdSql` | Раздел 4: три задачи сайта |
| JPQL | `ProjectRepository.findProjectsByEmployeeName` | Раздел 5: проекты Сайт и Бот |
| Транзакции в сервисе | `TrackerService`, `@Transactional` | Заполнение выполняется одной транзакцией, чтение через `readOnly = true` |
| Criteria API | `TrackerService.filterTasks` | Разделы 6-11, результаты ниже |
| Запускаемая демонстрация | `DemoRunner` | В конце выводится `Демонстрация завершена.` |

## Проверка динамических фильтров

| Раздел вывода | Параметры | Количество задач |
| --- | --- | --- |
| 6 | Все параметры `null` | 5 |
| 7 | Статус TODO | 2 |
| 8 | Статус TODO и проект Сайт | 1 |
| 9 | Название содержит `главную`, статус TODO и проект Сайт | 1 |
| 10 | Название из пробелов, пустой статус, проект `null` | 5 |
| 11 | Несуществующее название | 0 |

В `filterTasks` условия добавляются только для заполненных параметров. Поиск названия учитывает регистр. Статусы примеров: `TODO`, `IN_PROGRESS`, `DONE`.

Посмотреть таблицы напрямую:

```powershell
docker compose exec db psql -U student -d task_tracker -c "\dt"
docker compose exec db psql -U student -d task_tracker -c "SELECT * FROM participations ORDER BY id;"
```

Для просмотра SQL Hibernate при демонстрации:

```powershell
docker compose run --rm -e SPRING_JPA_SHOW_SQL=true app
```

В проекте выполнена обязательная часть задания. Схемой управляет `ddl-auto: update`. Веб-интерфейс, авторизация и интеграция с Git-хостингом не предусмотрены.
